# ペアワイズで組み合わせを作る

## 手順

1. **対象を確認する**
   `output/<案件>/scope.md`（スコープ判定）で「差あり」になっている軸だけを使う。差のない軸は入れない。

2. **モデルを作る** → `models/<案件>/<段階>.txt`
   - 値は `pack/classes/同値クラス.md` のクラスから取る（個々のキャリアではなくクラス）。
   - ありえない組み合わせは制約として書く。根拠（pack のファイル・行）を `#` コメントで残す。
   - 根拠が見つからない制約は書かず、`questions/質問のたね.md` に追記する。
   - 書式は PICT と同じ。例：`models/sample/購入.txt`

3. **必須の組み合わせを決める** → `models/<案件>/必須.tsv`
   `rulebook/優先度.md` の「高」や `pack/qa/過去不具合の傾向.md` から、3つ以上の条件が重なる怪しい組み合わせを入れる。空欄は自動で埋まる。

4. **生成と検証**
   - `pict` コマンドが使える場合：`pict models/<案件>/<段階>.txt /e:models/<案件>/必須.tsv`
   - 使えない場合（標準）：
     ```
     node tools/pairwise.js models/<案件>/<段階>.txt --include models/<案件>/必須.tsv --verify > output/<案件>/pairwise_<段階>.tsv
     ```
   - `--verify` の判定が **OK** であることを確認する。NG なら原因を報告し、出力を使わない。
   - 「実現不能として除外したペア」が出たら、制約が意図どおりか人に確認する。

5. **テストケースにする**
   各行を `schema/testcase.yaml` の形でケースにする。`設計技法: ペアワイズ`、`ペアワイズ行` に行番号を書く。
   クラスの値は `pack/classes` の代表（代表経路ID など）に置き換える。

6. **報告する**
   全組み合わせ数 → 生成行数、必須行、除外したペア、質問のたねに追加したもの。

## 注意

- `--seed` を変えると結果が変わる。案件内では同じシードを使い、使ったシードを報告に書く。
- `tools/pairwise.js` は PICT のうち、IF/THEN/ELSE、= <> IN NOT IN、AND OR NOT に対応。重み付け・否定値（~）・パラメータ同士の比較・3因子以上の網羅は未対応（必要なら PICT を使う）。
- `pack/` は書き換えない。
