# 技法の選び方

| 状況 | 技法 | 補足 |
|---|---|---|
| 1つの軸の値を絞る | 同値分割 | `pack/classes/` のクラスごとに代表を1つ |
| 数値・日付・年齢の区切りがある | 境界値分析 | 境目の両側を取る。年齢は基準日（予約日/搭乗日）も確認 |
| 軸が3つ以上ある | ペアワイズ | スキル `pairwise` を使う |
| 業務ルールの条件分岐 | デシジョンテーブル | 例：運賃規則×時期→払戻可否 |
| 状態が移り変わる | 状態遷移 | 例：予約→発券→変更→払戻 |

## ケース作成のルール

- 1ケースに期待結果は1つ。複数あれば分割する。
- 全ケースに根拠（pack のファイルと行、または要件ID）を付ける。根拠がないケースは作らない。
- 根拠が「推測」「要確認」なら、ケースの確度も同じにする。
- 無効クラス（弾くべき入力）のケースも作る。
